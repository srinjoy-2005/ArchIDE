# Changelog: July 28, 2026
**Author**: Gourav Roy

## 1. Compiler: Variable Naming & Correctness Fixes
- **Sequential Variable Names**: Replaced the ad-hoc `x_{node_id}` naming scheme with a clean sequential counter (`x_0`, `x_1`, ...) anchored to Kahn's topological order, guaranteeing deterministic and collision-free intermediate variable names.
- **Input Variable Deduplication**: Fixed the critical bug where two Input nodes with the same label (e.g. both named "Input") would both map to `x_input`, producing `x_3 = x_input + x_input` in the generated code. Nodes with duplicate labels are now suffixed with a counter: `x_input`, `x_input_2`, etc.
- **Single Return Statement**: Fixed the bug where multiple `OutputBlock` nodes each emitted their own `return` statement (making all but the first dead code). The compiler now collects all Output nodes and emits a single `return out_1, out_2` at the end of `forward()`.
- **Removed Label-Based Block Dispatch**: Eliminated the fragile fallback that used the user's display label to look up block types (e.g. `if "Split" in label`). `block_id` is now the only canonical dispatch key, making renaming a block in the UI safe.

## 2. Compiler: Shape Inference Pass
- **`shape_inference_pass()` Function**: Implemented a standalone shape inference pass in `compiler.py` that traverses nodes in Kahn order, propagates concrete shape tuples, and wraps `ValueError` from block `infer_shapes()` into a `ShapeError` with `node_id` and `node_label` for rich frontend reporting.
- **`ShapeError` Exception Class**: Co-introduced alongside Srinjoy's version during merge resolution to carry structured error metadata (`node_id`, `node_label`) distinguishing shape mismatches from generic graph errors.

## 3. ParamDef Schema: Section & Read-Only Fields
- **`read_only`, `section`, `description`** fields added to `ParamDef` in `models.py` (co-designed with Srinjoy's session 2). These enable the three-section properties panel pattern.

## 4. Block Definitions: Full PyTorch Signatures
- **`LinearBlock`**: Exposed `bias` as an advanced param; `emit_init` now generates `nn.Linear(in, out, bias=bias)`.
- **`Conv2DBlock`**: Exposed `stride`, `padding`, `dilation`, `groups`, `bias` as advanced params. Corrected the shape formula to the dilated convolution formula. `emit_init` now generates the full `nn.Conv2d(...)` call.
- **`GouravBlock` Removed**: Deleted the debug test block from `core.py` and `__init__.py`.

## 5. New API Endpoint: `/api/check`
- **`POST /api/check`**: Added to `main.py`. Runs the shape inference pass independently from code generation. Returns `{"ok": True, "node_shapes": {...}}` on success, or a structured HTTP 422 response on the first shape mismatch. Accepts a `CheckRequest` body model.

## 6. Frontend: Three-Section Properties Panel
- **`ParamInput` Component**: Extracted a reusable `ParamInput` component that reads `param.read_only`, `param.section`, and `param.description` to render appropriately: greyed-out with an "inferred" badge for shape params, editable for basic params.
- **Three Sections in `PropertiesPanel`**: Replaced the flat parameter list with three distinct rendered sections — **Tensor Shapes** (greyed-out, `section="shape"`), **Parameters** (`section="basic"`), and a collapsible **Advanced Properties** `<details>` element (`section="advanced"`).
- **Float param handling**: Fixed the `onChange` handler in `PropertiesPanel` to correctly call `parseFloat()` for `type="float"` params (previously only `parseInt` was used).

## 7. Frontend: "Run Static Tensor Check" Button
- **New Header Button**: Added a "Run Static Tensor Check" button in the `Header` component that calls `POST /api/check`. The button cycles through four visual states — `idle` (grey border), `checking` (disabled), `ok` (green border with ✓ message), `error` (red border with the mismatch message).
- **Shape Propagation Back to UI**: On a successful check, the frontend iterates over the `node_shapes` response and writes inferred shapes back into each node's `paramValues` for `input_shape` / `output_shape`. These are immediately visible in the greyed-out shape fields in the Properties Panel.
- **`buildPayload()` Refactor**: Extracted the common graph-to-JSON serialisation logic into a `buildPayload()` helper shared by both `handleExport` and `handleCheck`.

## 8. Merge Conflict Resolution
- Resolved three-way merge conflicts in `backend/compiler.py`, `backend/main.py`, and `src/app/page.tsx` after Srinjoy's branch diverged during concurrent development. Final merge kept the best of both: our sequential naming + single-return + `/api/check` endpoint, combined with Srinjoy's `ShapeError`, `_sanitize`, `_resolve_block_id`, and `var_hint`-based output naming.

## 9. Parameter Auto-Inference Engine
- **Backend Resolution**: Updated `shape_inference_pass` in `compiler.py` to detect when block `infer_shapes()` methods mutate `paramValues` (e.g., resolving `in_features=-1` to `in_features=64` based on the incoming edge shape).
- **API Support**: `POST /api/check` in `main.py` now returns both `node_shapes` and `node_params`.
- **Frontend Sync**: Updated `page.tsx` so that when the check endpoint returns `node_params`, the UI automatically updates the block's Properties Panel values with the auto-inferred dimensions.

## 10. Block Library Restructuring & Expansion
- **Reorganization**: Moved away from a single `tensor_ops.py` file. Organized blocks into dedicated PyTorch submodules: `activations.py`, `pooling.py`, `normalization.py`, and `shape.py`.
- **10 New Blocks Implemented**: 
  - **Activations**: `Sigmoid`, `Tanh` (also migrated `ReLU` and `Softmax`)
  - **Pooling**: `MaxPool2D`, `AvgPool2D`, `AdaptiveAvgPool2D`
  - **Normalization**: `BatchNorm2D` (with auto-infer support), `LayerNorm` (with auto-infer support), `Dropout`
  - **Shape Ops**: `Flatten`, `Reshape`
- **Block Tracking**: Created `docs/blocks_status.md` to track implemented and pending blocks.

## 11. Core Fixes
- **React Crash Fix**: Fixed a bug in `page.tsx` where rendering the structured `ShapeError` object from the backend directly into the DOM caused a React crash. Now correctly extracts the `.message` string.
- **InputBlock UX**: Removed the redundant greyed-out `output_shape` parameter from `InputBlock`. Enhanced the parsing logic for the editable `shape` parameter to aggressively strip invalid characters, making it highly robust (e.g., `1, 3, 224` and `(1,3,224)` both work flawlessly).
