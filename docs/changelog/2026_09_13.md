# Changelog: September 13, 2026

## Author: Antigravity

- **Variable Binding Fixes**: 
  - Fixed a critical bug in `backend/compiler.py` where variable substitutions into string parameters (like `shape`) were not written back during the Dual-Evaluation phase if they were not pure math expressions.
  - Implemented robust type-checking at variable binding time to prevent numeric variables (int/float) from being bound to string parameters (e.g. `shape`). This raises a clear `ShapeError` pointing to the exact node.
- **Frontend Validation**:
  - Updated `src/components/ExpressionInput.tsx` to surface variable type-mismatch errors in real-time, marking the input red and providing a tooltip if an incompatible variable type is used for a string parameter.
  - Filtered the variable autocomplete dropdown in `ExpressionInput` to only show compatible variable types for the parameter being edited.
- **Pooling Blocks Rank Guards**:
  - Reverted the strict 4D rank guards in `MaxPool2D`, `AvgPool2D`, `AdaptiveAvgPool2D`, and `BatchNorm2D` back to a permissive fallback (`"ANY"`). This correctly allows the `Input` block to propagate 1D, 2D, or 3D tensors through dynamic pipelines without triggering premature errors.
- **Test Suite Updates**:
  - Replaced `test_rank_mismatch_raises_error` with `test_pooling_returns_any_for_non_4d` in `backend/tests/test_blocks.py` to assert the newly reverted permissive fallback behavior.
- **Tensor Ops**:
  - Updated `var_hint` in `backend/blocks/tensor_ops.py` for the Add block output from `"sum"` to `"sum_out"`.

## Author: Gourav Roy

### 1. Shape Parameter Type & Variable Interpolation (Fixes #13)
- **First-Class `shape` Type**: Introduced `'shape'` as a supported parameter type in `src/lib/paramTypes.ts`, `backend/models.py`, and updated `InputBlock.shape` in `backend/blocks/core.py`.
- **Relaxed Expression Validation**: Updated `src/components/ExpressionInput.tsx` and `backend/compiler.py` to allow embedding `int` and `float` variables (e.g. `(1, @var:channels, 32, 32)`) into shape expressions without type mismatch errors.
- **Autocomplete Suggestions**: Updated variable autocomplete in `ExpressionInput.tsx` to populate numeric variables for shape and string parameters.

### 2. Resolution Mode & PyTorch Lazy Modules (Fixes #13)
- **3-Way Resolution Mode**: Replaced the binary "Auto-Infer" checkbox with an explicit Resolution Mode selector (`Manual`, `Static Bake-In`, `Lazy / Dynamic`) with contextual helper text in `src/components/PropertiesPanel.tsx`.
- **Lazy Module Codegen**: Updated `LinearBlock` and `Conv2DBlock` in `backend/blocks/core.py` to generate `nn.LazyLinear` and `nn.LazyConv2d` respectively when set to `"LAZY"`.
- **Compiler Passthrough**: Ensured `"LAZY"` mode parameters are preserved through code generation without being prematurely overwritten by design-time shape defaults.

### 3. Dynamic Tensor Dimension Extraction (Fixes #14)
- **`ShapeExtractorBlock`**: Implemented `ShapeExtractorBlock` in `backend/blocks/core.py` and registered it in `backend/blocks/__init__.py`. Dynamically extracts tensor dimensions (`shape`, `dim_0`, `dim_1`, `dim_2`, `dim_3`) during the `forward` pass for downstream reshaping.

### 4. Compiler Robustness & Multi-Module Fixes (Ref #15)
- **Import Fix**: Resolved `NameError: ParamDef` by importing `ParamDef` into `backend/compiler.py`.
- **Type Annotation Fix**: Mapped internal variable types to valid Python builtins (e.g. `string` -> `str`, `shape` -> `tuple`) in constructor generation.
- **Custom Module Naming**: Removed the `[:8]` node ID slice in `CustomModuleBlock` to prevent instance variable name collisions when multiple custom blocks exist in the same graph.
- **Submodule Variable Passthrough**: Updated `CustomModuleBlock.infer_shapes` to pass child graph variables into `shape_inference_pass`.
- **Embedded Usage Tracking**: Updated `getUsages` in `src/components/VariablesPanel.tsx` to detect variable occurrences inside shape expressions.

### 5. Verification & Live Model Testing
- **Automated Tests**: Added `backend/tests/test_lazy_and_shape_extractor.py` (7 tests). All 32 backend tests and `npx tsc --noEmit` pass with 0 errors.
- **Live Transformer Execution**: Verified live forward and backward passes (`torch.randn(1, 64, 512)` -> `[1, 64, 3000]`) on a multi-module Transformer architecture using PyTorch in `C:\MachineLearning\.venv`.
