### 🐛 Bug Fix: `LinearBlock` Silent Shape Mismatch
**File:** `backend/blocks/core.py` — `LinearBlock.infer_shapes`

**Root Cause:** `LinearBlock.infer_shapes` only validated `in_shape[-1]` (the last dimension), meaning a 4D tensor `(B, C, H, W)` from a Conv2D/Pool output would silently pass shape checking. The last spatial dimension (e.g. `222`) was accepted as `in_features` and no error was raised, despite `nn.Linear` strictly requiring a 2D `(Batch, Features)` input. This produced syntactically valid but runtime-broken PyTorch code.

**Fix:** Added a dimensionality guard that raises a `ValueError` with a clear, actionable message whenever a tensor with more than 2 known dimensions is passed to `LinearBlock`:
> *"Linear expects a 2D tensor (Batch, Features), but received a 4D tensor with shape [...]. Add a Flatten node between the previous layer and this Linear layer."*

The guard correctly skips the check when any dimension is `"ANY"` (unknown), preserving permissive behaviour for partially-resolved graphs.

### �� Bug Fix: `loadStarter` Missing Flatten Node
**File:** `src/app/page.tsx` — `ModelSummaryDashboard.loadStarter`

**Root Cause:** The "Load ConvNet Pipeline" demo template loaded the graph `Input → Conv2D → ReLU → Linear → Output`, which is architecturally incorrect. `nn.Linear` cannot accept the 4D output of Conv/ReLU. The old template also incorrectly used `in_features: -1` directly on a 4D tensor, which caused the auto-inference to silently pick up the wrong last dimension (e.g. `222`), producing `nn.Linear(222, 10)` — a plausible-looking but wrong value.

**Fix:** Inserted a **Flatten** node (with `start_dim=1, end_dim=-1`) between the ReLU and Linear nodes. The updated pipeline is:
```
Input → Conv2D → ReLU → Flatten → Linear (in_features=-1) → Output
```
The Linear node now correctly auto-infers `in_features` from the 2D output of Flatten, and the shape checker will fully validate this end-to-end.
